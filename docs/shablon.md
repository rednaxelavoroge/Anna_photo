# Сайт фотографа — шаблон

Это код сайта с панелью управления: фотограф сам добавляет кадры, ролики,
разделы, отзывы и тексты, а сайт после каждого сохранения пересобирается и
выкладывается на обычный хостинг.

Собран из готового сайта annamanasaryan.com. Чужого содержимого здесь нет:
ни фотографий, ни текстов, ни контактов, ни доступов — только код и пустые
заготовки данных.

## Что это умеет

- Портфолио разделами и подразделами, лента «все кадры», альбомы.
- Панель на отдельном адресе: кадры, разделы, подразделы, бэкстейдж,
  отзывы, обучение, «обо мне и СМИ», фототуры, контакты.
- Загрузка фотографий прямо из панели: браузер их ужимает, файл уезжает в
  репозиторий, сайт пересобирается сам.
- Загрузка роликов с телефона (до 200 МБ): исходник уезжает в служебный
  выпуск GitHub, машина сборки сжимает его, делает обложку и кладёт готовый
  ролик на сайт.
- Обложки роликов картинками — в панели и на сайте вместо чёрных
  прямоугольников.
- Превью загруженного видно сразу, ещё до выкладки, и переживает
  перезагрузку страницы.
- Защита от затирания: панель не пишет поверх правок, сделанных за её
  спиной.

## Устройство в двух словах

Next.js 15 (App Router) + Tailwind 4. Две сборки из одного кода:

- **сайт** — `NAMECHEAP_EXPORT=1`, папка готовых файлов, кладётся на обычный
  хостинг по FTP;
- **панель** — `PANEL_BUILD=1`, маленький сервер Node (`standalone`),
  живёт на поддомене вида `admin.домен` в приложении Node.js в cPanel.

Данные сайта — восемь файлов JSON в `src/data`. Панель читает и пишет их
через GitHub API, поэтому каждое сохранение — обычный коммит, и любую правку
видно в истории и можно откатить.

## Запуск на своей машине

```bash
npm install
npm run fonts     # скачает шрифты в public/fonts
npm run dev       # http://localhost:3000, панель — /admin
```

Для входа в панель задайте `ADMIN_PASSWORD` в `.env.local`. Без него вход
закрыт — так и задумано.

## Что поменять под нового фотографа

1. **Тексты, разделы, контакты.** Всё через панель, руками в JSON лезть не
   надо. В `src/data/site.json` заранее вписаны заглушки: имя, домен,
   контакты.
2. **Домен.** `src/data/site.json` → `domain`; из него берутся карта сайта и
   robots.
3. **Адрес панели.** `public/.htaccess` — строка с переадресацией `/admin`
   на поддомен панели.
4. **Репозиторий и ветка.** В `.github/workflows/*.yml` вписаны имя
   репозитория и рабочая ветка исходного проекта. Найти всё разом:

   ```bash
   grep -rn "rednaxelavoroge/Anna_photo\|cursor/namecheap-static-f40b\|annamanasaryan" .github src public/.htaccess
   ```

5. **Приметы папки сайта.** Выкладка ищет папку на хостинге и отказывается
   работать, если попала не туда: проверяет `index.html` и раздел
   `phototour`, а имена чужих сайтов держит в стоп-листе. Приметы поменяйте
   на свои — это защита от выкладки поверх чужого сайта, убирать её нельзя.
6. **Секреты репозитория** (Settings → Secrets → Actions):
   - `FTP_HOST`, `FTP_USER`, `FTP_PASSWORD` — доступ к хостингу сайта;
   - `PANEL_FTP_USER`, `PANEL_FTP_PASSWORD`, `FTP_PANEL_DIR` — если у панели
     свой доступ или своя папка;
   - `PANEL_MEDIA_BASE` — адрес сайта, откуда панель берёт фотографии;
   - `GITHUB_TOKEN` не нужен: у процессов есть свой.
7. **Переменные приложения панели в cPanel:** `ADMIN_PASSWORD`,
   `GITHUB_TOKEN` (право `repo`), `GITHUB_REPO`, `GITHUB_BRANCH`,
   `NEXT_PUBLIC_MEDIA_BASE`. Образец — `.env.example`.

## Выкладка

- **Сайт** — сам на каждый push в рабочую ветку, плюс кнопка в Actions.
- **Панель** — только кнопкой в Actions. Тронули что-нибудь в
  `src/components/admin/**`, `src/app/admin/**`, `src/app/api/admin/**` или
  `src/lib/admin-*` — запустите выкладку панели, иначе на хостинге останется
  прежняя сборка.

## Полезные команды

```bash
npm run typecheck              # проверка типов
npm run export:namecheap       # собрать папку сайта для хостинга
node tools/make-posters.mjs    # обложки для роликов, лежащих в public
node tools/import-folders.mjs  # разложить фотографии из папок по разделам
node tools/make-template.mjs   # собрать такой же шаблон из своего проекта
```

## Что стоит знать заранее

- **Обложка ролика — обязательна.** Проигрыватель без неё рисует чёрный
  прямоугольник: браузер не показывает кадр, пока ролик не тронули.
  Обложки делает `tools/make-posters.mjs` и рабочий процесс сжатия.
- **Фотографии лежат в репозитории.** Это удобно (история, откат), но
  репозиторий растёт. Гигабайты кадров — нормально, десятки — уже нет.
- **Панель пишет в ту же ветку, что читает.** Если правите код в это же
  время, тяните её правки перед push.
